# FTA/ETA Editor v1.6 — Web Application Specification

**Status:** Draft for review
**Date:** 2026-09-07
**Supersedes:** nothing — v1.6 is *additive*
**Baseline:** v1.5.1 (`e5f655f`)

---

## 1. Purpose

v1.6 delivers a browser-based FTA/ETA Editor that is a functional equivalent of
`src/FTA_Editor_UI.py`, built on Flask, and distributable to users who do not have
Python installed.

### 1.1 Hard constraint: complete isolation

**All v1.6 code lives inside a single new top-level directory, `fta_web/`, and has
zero imports from anywhere outside it.** No file under `src/`, `tests/`, or `data/` is
read at runtime, modified, or depended upon. The existing codebase is frozen in place;
the Tkinter desktop app must continue to run exactly as it does today.

Isolation is achieved by **vendoring**: `fta_web/core/` holds byte-level copies of the
four `src/` modules the web app needs, taken at baseline `e5f655f`. `fta_web/` is
therefore independently movable — it can be zipped, relocated, or shipped without
`src/` present.

Two guards keep this honest, because a fork with no guard rots silently (§4.6):

1. **Upstream freeze check** — the SHA-256 of every `src/*.py` file is pinned in a
   manifest. If anyone edits the original tree, CI fails. *This* is what enforces the
   freeze.
2. **Vendor pin + divergence manifest** — the vendored copies are pinned to their own
   hashes, and every intentional patch is recorded in `fta_web/core/DIVERGENCE.md` with
   its rationale. Unplanned edits fail; deliberate ones are documented and opted into.

**Because the vendored core is owned by v1.6, it may be repaired.** The defects listed
in §12 are fixed in `fta_web/core/`, not merely documented. The desktop app keeps its
current behavior; §12 records each divergence.

One consequence survives isolation. Three behaviors the web app needs live *inside*
`FTA_Editor_UI.py`, which is a Tkinter UI and is deliberately **not** vendored. They are
written fresh in `fta_web/tree_ops.py` — see §4.2.

### 1.2 Two tools, not one product

**The desktop app and the web app are separate tools with separate lifecycles.** They
are not two frontends over a shared product, and nothing in this spec should be read as
an obligation to keep them aligned.

This is the intent behind the isolation, and it settles several questions that would
otherwise be open:

- **Divergence is expected, not a hazard.** Once `fta_web/` owns its core, the two tools
  are free to disagree. The guards in §4.6 exist to keep divergence *documented*, not to
  prevent it.
- **Nothing is back-ported.** A fix landing in `fta_web/core/` stays there. `src/` is
  frozen for the duration of v1.6 and is not maintained afterward.
- **File compatibility still matters; output parity does not.** Users must be able to
  move `.json` analyses between the tools while both exist (§9). Byte-identical Excel or
  diagram output is explicitly *not* a goal — see §12, defect 3.

**After v1.6 ships, the desktop app is deprecated but retained.** It stays in the
repository, runnable, for users who depend on it. It receives no further features and no
further fixes. §15 carries the deprecation checklist.

### 1.3 Decisions this spec is built on

| # | Decision | Choice |
|---|----------|--------|
| 1 | Runtime model | Local single-user; Flask on `127.0.0.1`, auto-opens browser |
| 2 | AI credentials | Optional; entered on first use, persisted for subsequent runs |
| 3 | Diagram rendering | Graphviz-WASM in browser, native `dot` preferred when detected |
| 4 | Frontend stack | Vanilla JS ES modules + Jinja2 — no Node, no build step |
| 5 | Scope | Desktop parity **plus** web-native editing (undo, drag, inline edit, search) |
| 6 | File I/O | Server-side filesystem picker, with browser download as export path |
| 7 | Layout | Same regions as desktop, modern styling |
| 8 | Languages | English + Japanese, switchable at runtime |
| 9 | Testing | pytest: existing 35 tests stay green, plus API coverage for every endpoint |
| 10 | Desktop app | Frozen through v1.6, then deprecated but retained — a separate tool (§1.2) |
| 11 | Distribution | PyInstaller **onedir**, plus a plain `python fta_web/run.py` path |
| 12 | Isolation | Complete — `fta_web/` vendors its core; zero imports outside the folder |
| 13 | Baseline defects | Fixed in the vendored copy, documented as divergences (§12) |

### 1.4 Non-goals

- Multi-user access, accounts, authentication, or a database
- Cloud/hosted deployment (Render, Heroku); v1.5.1 removed that path and v1.6 does not restore it
- Real-time collaboration or concurrent editing
- Changing probability semantics, the JSON schema, or any export format
- Back-porting the vendored fixes to `src/` — the desktop app stays exactly as it is

## 2. What the desktop app does today

The v1.6 web app must reproduce all of the following. This is the parity checklist
that §13 tests against.

### 2.1 Metadata bar
Mode selector (`FTA` / `ETA`), title, date, and a "Hide Zero P_calc" display toggle.
Changing the mode triggers a full probability recalculation and relabels the tree
panel ("Fault Tree" ↔ "Event Tree").

### 2.2 Tree panel
Hierarchical view with per-depth background colors (8 colors cycling, up to 20 levels),
a `✖` marker column for zero-probability nodes, blue text for zero-probability nodes,
and bold red text for nodes whose base probability is exactly 1.0.

### 2.3 Node dialog
Name, type, probability (validated `0 ≤ p ≤ 1`), logic gate (`AND`/`OR`), notes, and a
links editor: a searchable list of all nodes in the tree, with separate AND-links and
OR-links lists and add/remove controls.

### 2.4 Diagram preview
Live PNG preview regenerated after every mutation, plus an explicit "Render Img" action
that produces a high-DPI (300 dpi) render in a separate window with zoom, pan, and
save-as-PNG.

### 2.5 File operations
New / Load JSON / Save / Save As, export to XML and Excel, and an unsaved-changes
guard that prompts Yes / No / Cancel before any destructive navigation.

### 2.6 AI assistant
Chat panel with conversation history, a settings dialog (provider, API key, endpoint,
model, with dynamic model-list fetching and a connection test), and three quick actions:

- **Analyze FTA** — posts an assessment to chat; never modifies the tree
- **Update FTA** — asks the AI for a complete replacement JSON, validates it, and applies it wholesale
- **Clear Chat** — resets both the display and the conversation history

### 2.7 Keyboard shortcuts
`Ctrl+N` new · `Ctrl+A` add · `Ctrl+E` edit · `Ctrl+D` delete · `Ctrl+S` save · `Ctrl+R` render

## 3. Architecture

### 3.1 Process model

A single Flask process bound to `127.0.0.1` on an ephemeral free port. `fta_web/run.py`
picks the port, generates a session token, starts the server, and opens the default
browser at `http://127.0.0.1:<port>/?t=<token>`.

Because there is exactly one user, **application state is a single in-process object.**
There are no Flask sessions, no `flask-session`, no filesystem session store, and no
serialization of the tree into a cookie. This removes the entire class of problem the
v1.5.1 web app fought with (see `git show 34033a0` — "Fix session state persistence for
Render.com multi-worker environment").

The server must therefore run **single-worker**. This is asserted at startup; a
multi-worker launch is refused with a clear error rather than silently corrupting state.

### 3.3 The vendored core

Four of the five `src/` modules are copied into `fta_web/core/` at baseline `e5f655f`.
**`FTA_Editor_UI.py` is deliberately not vendored** — it is a Tkinter UI with no role in
a web app, and vendoring it would imply a maintenance obligation v1.6 does not accept.

| Vendored module | Baseline SHA-256 | Role in v1.6 |
|-----------------|------------------|--------------|
| `FTA_Editor_core.py` | `51ce55d9…2e2ff2` | All tree state, probability calculation, JSON/XML/Excel I/O |
| `json_viewer.py` | `a4f18f2f…f84191` | `gather_nodes` and `build_dot`, **imported as functions** |
| `AI_agent_handler.py` | `492dcceb…12017ee` | Wrapped by `ai_bridge.py`; also supplies `AICredentialManager` |
| `ai_providers.py` | `87733070…8a2b4c2` | Provider and model dropdowns via `AIProviderFactory` |

**Packaging.** `fta_web/core/` is added to `sys.path` by `config.py`. This matters
because exactly one cross-module import exists in the vendored set —
`AI_agent_handler.py:17`, `from ai_providers import AIProviderFactory`. Putting the
directory on the path lets that line work unchanged, so packaging contributes **zero**
divergence from baseline. Every difference in `DIVERGENCE.md` is then a deliberate
defect fix, never an artifact of how the files were arranged.

Filenames are kept verbatim so that `diff src/X.py fta_web/core/X.py` stays directly
meaningful for anyone auditing the fork.

**Note the subprocess elimination.** The desktop app spawns
`sys.executable json_viewer.py` on *every* preview update
(`FTA_Editor_UI.py:1154`), paying interpreter-startup cost per keystroke-level change.
v1.6 imports `gather_nodes` and `build_dot` in-process instead. Both are pure functions
over dicts with only stdlib imports, so this is safe and considerably faster.

## 4. Server-side logic

### 4.1 `state.py` — AppState

Single instance, created at startup, holding:

| Field | Purpose |
|-------|---------|
| `core` | The live `FTACore` instance |
| `current_path` | Path of the last opened/saved file, or `None` |
| `dirty` | Unsaved-changes flag, mirroring the desktop's `has_unsaved_changes` |
| `undo_stack` / `redo_stack` | Snapshot deques, max 50 entries each |
| `native_dot` | Path to a system `dot`, or `None` (probed once at startup) |
| `language` | `"en"` or `"ja"` |

A mutation lock (`threading.Lock`) serializes all state-changing requests. Browsers
issue concurrent fetches freely; without this, two in-flight mutations can interleave
and corrupt the tree.

**Undo/redo is snapshot-based.** Before each mutation, `copy.deepcopy` of the tree plus
metadata is pushed onto `undo_stack` and `redo_stack` is cleared. FTA trees are small
(tens to low hundreds of nodes), so full snapshots are simpler and more obviously
correct than a command/inverse-command log, at negligible memory cost.

### 4.2 `tree_ops.py` — logic written fresh from the Tkinter layer

These three behaviors exist **only** inside `FTA_Editor_UI.py`, which is not vendored
(§3.3), and are coupled to the `ttk.Treeview` widget. They are written fresh here
against the plain data structure. Implementers should read the originals side by side.

They live in `tree_ops.py` rather than being added to the vendored core, per the
discipline in §4.6: the vendored files carry defect fixes only, so that a diff against
baseline shows exactly the intended repairs and nothing else.

**a) `next_child_id(parent_id) -> str`**
Original: `FTA_Editor_UI.py:1414-1424`. Scans the parent's existing children for IDs
matching `<parent_id>_<n>`, takes the maximum `n`, and returns `<parent_id>_{n+1}`.
The original reads children off the Treeview; the port reads them from
`core.find_node_by_id(parent_id)["children"]`. Behavior — including the ID format that
`_normalize_node` also produces (`FTA_Editor_core.py:344`) — must match exactly, so
files round-trip identically between the two apps.

**b) `depth_of(node_id) -> int`**
Original: `FTA_Editor_UI.py:1613-1619`, which walks Treeview parents up to `'root'`.
The port walks the data tree instead. Used for the per-level color tags.

> Fix while porting: the original is inconsistent about depth capping. `_apply_zero_marks`
> uses `min(depth, 3)` (`:1568`) and `_refresh_tree` uses `min(depth+1, 3)` (`:1594`),
> capping colors at 4 levels, while `_apply_change` (`:744`) and `_rebuild_subtree`
> (`:1517`) use the uncapped depth. The tag table itself defines 20 levels (`:180`).
> **v1.6 uses the uncapped depth everywhere**, which is what the 20-level table intends.

**c) `apply_ai_change(core, change) -> (bool, str)`**
There are currently **two divergent implementations** of applying an AI-proposed change:

- `FTA_Editor_UI.py:706` `_apply_change` — validates against the Treeview widget, supports add/edit/delete
- `AI_agent_handler.py:695` `apply_change_to_fta` — validates against `FTACore`, supports add/edit/delete/**move**, includes circular-reference detection, and **is never called by the UI**

v1.6 standardizes on `AIAgentHandler.apply_change_to_fta`. It is already widget-free,
already handles the case the UI version misses, and lives in an unmodified file. No new
code is needed for this behavior — only the decision to use it.

**d) `move_node(node_id, new_parent_id, index)`** — new in v1.6, for drag-to-reparent.
Reuses the cycle guard already present at `AI_agent_handler.py:827`
(`_would_create_circular_reference`). Rejects moving `root`, moving a node into its own
descendant, and any unknown target.

### 4.3 Invariants preserved from the desktop app

These are load-bearing and must not drift:

1. **Root node ID is always the literal string `"root"`.** `verify_updated_fta_json`
   rejects any tree whose root is named otherwise (`AI_agent_handler.py:959`).
2. **Root default probability is `1.0`**, not `0.0` (`FTA_Editor_core.py:37`).
3. **In FTA mode, a parent with children ignores its own base probability.** The value
   is derived solely from the gate and the children (`FTA_Editor_core.py:152-186`).
   An empty, missing, or `None` gate is treated as `OR`. *Modified by the defect 5 fix:
   `NOT` is no longer swept into the `OR` branch — see §12.*
4. **In ETA mode, a node's calculated probability is the running product** of its own
   base probability and its parent's calculated probability
   (`FTA_Editor_core.py:229-239`).
5. **Link cycles are tolerated, not rejected.** The `visiting` set
   (`FTA_Editor_core.py:157`) breaks recursion by falling back to the node's base
   probability. The web UI must not add stricter validation that rejects trees the
   desktop app accepts.
6. **AND links are applied before OR links** (`FTA_Editor_core.py:204-211`).
7. **Probabilities are rounded to 6 decimal places** at each calculation step.

### 4.4 `rendering.py`

```
tree (dict)
   └─> gather_nodes(root, hide_zero)        [json_viewer, imported]
   └─> build_dot(nodes, edges)              [json_viewer, imported]
   └─> inject title/date/font header        [replicated from json_viewer.main]
   └─> DOT text
         ├─> GET /api/dot   → browser → @hpcc-js/wasm → SVG      (default path)
         └─> native dot     → -Tsvg / -Tpng -Gdpi=300            (when available)
```

At startup, `shutil.which("dot")` is probed once and the result stored on `AppState`.
`GET /api/state` reports it as `nativeDot: true|false` so the client can label the
diagram source in the UI.

- **Default path (always available):** the browser fetches DOT text and renders it with
  vendored `@hpcc-js/wasm`. Zero install, works offline, no CDN.
- **Native path (when `dot` is present):** the server renders instead. Gains exact CJK
  glyph metrics from real system fonts, and true `-Gdpi=300` raster output matching the
  desktop's "high quality" mode.
- **PNG export without native `dot`:** serialize the live SVG, draw to a `<canvas>` at a
  chosen scale factor, and `toBlob()`. Produces arbitrary-resolution output.

Known limitation to document in the UI: WASM Graphviz has no font files and estimates
CJK glyph widths from built-in metric tables, so Japanese/Chinese/Korean node boxes may
be slightly loose or tight. Glyphs themselves render correctly — the browser resolves
`Noto Sans CJK JP` when painting the SVG. Only box sizing is approximate, and installing
Graphviz removes the approximation.

### 4.5 `security.py`

The app binds to localhost and exposes filesystem read/write endpoints. That combination
is exactly what a malicious page in another browser tab would like to reach, so three
controls are mandatory and non-optional:

1. **Bind `127.0.0.1` only.** Never `0.0.0.0`.
2. **Session token.** A `secrets.token_urlsafe(32)` generated per launch, delivered in
   the launch URL, stored by the page in `sessionStorage`, and sent as an
   `X-FTA-Token` header on every `/api/*` call. Requests without it get `403`. This is
   what stops a drive-by page from driving the editor.
3. **Origin/Host validation.** Reject any request whose `Origin` or `Host` is not the
   expected `127.0.0.1:<port>`, which blocks DNS-rebinding attacks that would otherwise
   defeat the localhost binding alone.

Filesystem endpoints additionally:

- Resolve every path with `Path.resolve()` and reject symlink escapes
- Refuse to traverse above a configured root (default: user home; overridable via `--root`)
- Enforce an extension allowlist on write: `.json`, `.xml`, `.xlsx`, `.png`, `.svg`
- Cap upload size at 10 MB

### 4.6 Vendoring discipline

The fork is only safe if its relationship to baseline stays legible. Four rules:

**1. Vendored files carry defect fixes only.** New functionality goes in new modules
(`tree_ops.py`, `rendering.py`, `ai_bridge.py`). A diff of `fta_web/core/X.py` against
`src/X.py` must show exactly the repairs in §12 and nothing else.

**2. Every divergence is recorded.** `fta_web/core/DIVERGENCE.md` carries one entry per
patch: the defect number, the affected lines, the before/after behavior, and why. A
reviewer who reads only that file understands the whole fork.

**3. Both directions are pinned.** `fta_web/core/BASELINE.json` holds two hash sets —
the upstream `src/*.py` files as of `e5f655f`, and the vendored files as patched:

```json
{
  "baseline_commit": "e5f655f",
  "upstream": {
    "src/FTA_Editor_core.py":  "51ce55d9b91404240d96548b8950a79ba2fc636e1d025bd6e62f04081b2e2ff2",
    "src/json_viewer.py":      "a4f18f2fbf68c38018676329be5206be1ae04048d8839758059fd4ce14f84191",
    "src/AI_agent_handler.py": "492dcceb72e597bfa0a0461a0385c15a7c440d3ed72f168398400407f12017ee",
    "src/ai_providers.py":     "87733070411e444987fe1e730b39c16ea3b173877e2177db93cf1bdeb8a2b4c2"
  },
  "vendored": { "…": "recomputed whenever a documented patch lands" }
}
```

`test_vendor_integrity.py` asserts both sets. An upstream mismatch means someone broke
the freeze. A vendored mismatch means someone patched the fork without documenting it.
Neither is allowed to pass silently.

**4. Updating a pin is a deliberate act.** Changing a vendored hash requires a matching
`DIVERGENCE.md` entry in the same commit. Reviewers should reject a hash bump that
arrives alone.

### 4.7 `ai_bridge.py`

Wraps `AIAgentHandler` and enforces one rule the desktop app never had to think about:
**the API key is never sent to the browser.** `GET /api/ai/credentials` returns
`{configured, provider, endpoint, model, keyPreview: "sk-…AB12"}` and nothing more.

**Credential storage.** Reuses `AICredentialManager` unchanged, so the key lands in
`~/.fta_editor/ai_credentials.json` — the same file the desktop app reads. Configure the
key in either app and both pick it up. On first launch with no key present, the AI panel
renders in a configured-off state with a "Set up AI" prompt; **every non-AI feature works
fully without a key.**

**Do not call `AIAgentHandler._get_client()`** (`AI_agent_handler.py:365`). It references
`self._client`, which `__init__` never assigns, and raises `AttributeError` on the first
call. It is dead code left over from the pre-provider-abstraction design; the live path
is `_get_provider()`. It is listed in §12 as an inherited defect.

AI calls run in a worker thread with a 120-second timeout so a hung provider cannot block
the single-threaded state lock.

## 5. HTTP API

All endpoints require the `X-FTA-Token` header. All responses are JSON except file
downloads. Errors use one envelope:

```json
{ "ok": false, "error": { "code": "NODE_NOT_FOUND", "message": "…", "detail": {} } }
```

### 5.1 State and metadata

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/api/state` | Full snapshot: tree, metadata, `dirty`, `currentPath`, `nativeDot`, `aiConfigured`, `canUndo`, `canRedo`, `language` |
| `POST` | `/api/metadata` | Set `title` / `date` / `mode`; a mode change recalculates and returns the updated tree |
| `POST` | `/api/new` | Reset to a fresh analysis; `409` if dirty unless `force: true` |

### 5.2 Nodes

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/api/nodes` | Flat `[{id, name, depth}]` for the links picker and search |
| `GET` | `/api/nodes/<id>` | One node with `calculatedProbability` and resolved link target names |
| `POST` | `/api/nodes` | Add under `parentId`; server assigns the ID via `next_child_id` |
| `PATCH` | `/api/nodes/<id>` | Update name / type / probability / logicGate / notes / links |
| `DELETE` | `/api/nodes/<id>` | Delete a subtree; `400` on `root` |
| `POST` | `/api/nodes/<id>/move` | Reparent to `newParentId` at `index`; `400` on cycle |

Every mutation recalculates probabilities and returns
`{ok, tree, zeroNodes, dirty, canUndo, canRedo}` so the client never needs a follow-up
fetch.

### 5.3 Undo / redo

| Method | Path |
|--------|------|
| `POST` | `/api/undo` |
| `POST` | `/api/redo` |

### 5.4 Rendering

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/api/dot?hideZero=<bool>` | DOT source text for the WASM renderer |
| `POST` | `/api/render` | Native render — `{format: "svg"\|"png", hideZero, highQuality}`; `503` when no native `dot` |

### 5.5 Files

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/api/fs/list?path=` | Directory listing for the in-app picker: dirs plus `.json` files |
| `GET` | `/api/fs/home` | Home and last-used directory, for picker startup |
| `POST` | `/api/file/open` | Load `{path}` via `core.load_from_json` |
| `POST` | `/api/file/save` | Save to `currentPath`; `409` if none set |
| `POST` | `/api/file/save-as` | Save to `{path}` and adopt it as `currentPath` |
| `GET` | `/api/export/json\|xml\|xlsx` | Download as attachment |
| `POST` | `/api/import/json` | Multipart upload fallback |

`load_from_json` already handles UTF-8-BOM, CP932, Shift-JIS and CP1252, plus
double-brace-wrapped JSON (`FTA_Editor_core.py:286-298`). That behavior is inherited
free — do not reimplement encoding detection client-side.

### 5.6 AI

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/api/ai/providers` | Provider list with default endpoints and models |
| `GET` | `/api/ai/models?provider=&` | Live model list; falls back to defaults on error |
| `GET` | `/api/ai/credentials` | Masked configuration status — never the key |
| `POST` | `/api/ai/credentials` | Test then save; mirrors the desktop "Test & Save" |
| `DELETE` | `/api/ai/credentials` | Clear stored credentials |
| `POST` | `/api/ai/chat` | Send a message; returns reply plus parsed proposed changes |
| `POST` | `/api/ai/analyze` | Analyze FTA — reply only, never mutates |
| `POST` | `/api/ai/update` | Full-JSON update: generate, verify, apply |
| `POST` | `/api/ai/changes/apply` | Apply selected proposed changes by index |
| `DELETE` | `/api/ai/conversation` | Clear chat history |

`/api/ai/update` must reproduce the desktop error reporting at
`FTA_Editor_UI.py:855-895`: on a parse failure return the first 500 characters of the
raw AI output; on a validation failure return the validator message *and* the JSON of
the specific offending node, located by the node ID parsed out of the error string.
That diagnostic detail is the feature — do not reduce it to "invalid JSON".

## 8. Distribution

### 8.1 Developer path

```bash
pip install -r requirements.txt -r fta_web/requirements.txt
python fta_web/run.py            # picks a free port, opens the browser
python fta_web/run.py --port 5000 --no-browser --root ~/projects
```

New dependencies: **Flask only.** No `flask-session` (single-user, no session store),
no Node, no bundler.

### 8.2 End-user executable

PyInstaller **onedir** — explicitly not onefile. Onefile re-extracts the whole bundle to
a temp directory on every launch, which is slow and reliably trips antivirus heuristics.
Onedir starts fast and is transparent to security software.

```
FTA_Editor_v1.6_win64/
├── FTA_Editor.exe          # launches Flask + browser
├── _internal/              # Python runtime, Flask, app code
└── README.txt
```

`build/fta_editor.spec` declares `fta_web/templates`, `fta_web/static` (including the
vendored WASM) and `fta_web/examples/` as `datas`, with a runtime hook that resolves paths
through `sys._MEIPASS` when frozen.

**Because rendering falls back to WASM, the executable has no native prerequisite.**
That is the whole reason §1.2 decision 3 was made this way. Graphviz remains an optional
enhancement: install it and the app silently upgrades to native rendering.

Build targets: Windows x64 primary; macOS and Linux documented but built on demand.

### 8.3 First-run experience

1. User unzips and runs `FTA_Editor.exe`
2. Browser opens to a new empty analysis — no configuration, no prompts
3. The AI panel shows "Set up AI (optional)"; every other feature is fully usable
4. If the user configures a key, it persists to `~/.fta_editor/ai_credentials.json` and is picked up on every later launch — by this app and by the desktop app


## 12. Divergence register

The vendored core is owned by v1.6, so these defects are **fixed**, not merely
documented. `src/` keeps every one of them; the desktop app's behavior is unchanged.

Each fix below becomes one entry in `fta_web/core/DIVERGENCE.md` and one vendored hash
update in `BASELINE.json`, per §4.6.

### 12.1 Fixed in the vendored core

| # | Location | Defect | Fix | Behavior change |
|---|----------|--------|-----|-----------------|
| 1 | `AI_agent_handler.py:365` | `_get_client()` reads `self._client`, never assigned in `__init__` → `AttributeError` if called. Dead code from the pre-provider-abstraction design. | Delete the method. | None — it was unreachable. |
| 3 | `FTA_Editor_core.py:477-553` | Excel export's `current_row` bookkeeping does not account for subtree height, so deep sibling subtrees can overwrite each other's rows. | Compute each subtree's row span before writing siblings. | **Yes.** Excel output differs from the desktop app for trees with multi-level siblings. Shallow trees are unaffected. |
| 5 | `AI_agent_handler.py:596` vs `FTA_Editor_core.py:348` | The AI validator accepts `logicGate: "NOT"`, but the engine treats anything that is not `AND` as `OR`. **A `NOT` gate silently computes as `OR`** — a wrong number, not a visible error. | Either implement `NOT` as `1 − p`, or reject it at validation. **Decide before P0**; see below. | **Yes**, for any tree containing a `NOT` gate. |
| 6 | vendored `tests/core/` | Four tests `return True` instead of asserting, so they pass regardless of outcome. | Convert to real assertions. | None — but two may start failing, which is the point. |

### 12.2 Resolved by not vendoring the UI

| # | Location | Why it evaporates |
|---|----------|-------------------|
| 2 | `FTA_Editor_UI.py:706` vs `AI_agent_handler.py:695` | Two divergent apply-change implementations. `FTA_Editor_UI.py` is not vendored, so only the complete widget-free version exists in `fta_web/`. |
| 4 | `FTA_Editor_UI.py:1568`, `:1594` | Depth capped at 4 in two of four code paths despite a 20-level tag table. Not vendored; `tree_ops.depth_of` is uncapped by design (§4.2). |

### 12.3 Open decision — defect 5

`NOT` is ambiguous and the fix should not be guessed at.

- **Implement it** as `1 − p` — the standard complement gate. Correct, but a `NOT` with multiple children is undefined and needs its own rule.
- **Reject it** at validation, so a `NOT` gate becomes a loud error instead of a silent wrong answer.

**Recommendation: reject it in v1.6.** No existing sample or test uses `NOT`, the AI
prompt never suggests it (`AI_agent_handler.py:307` offers only `AND|OR`), and a
rejection cannot compute a wrong probability. Implementing a complement gate is a
feature, not a defect fix, and belongs in v1.7 with its own semantics for the
multi-child case.

## 14. Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| WASM CJK metrics are visibly wrong, not just loose | Japanese users see broken diagrams | Validate against real Japanese data in P2, *before* the frontend depends on it. Native `dot` fallback already exists; if it fails badly, escalate to bundling a font-metrics table. |
| `fta_web/js/main.js` grows into a second 1900-line monolith | Same maintenance problem, new language | Module boundaries fixed in §3.2; enforce a soft 300-line-per-module cap in review |
| Vendored WASM (~2.5 MB) bloats the repo | Slow clones | Single commit, never re-vendored casually; pin the version in `fta_web/requirements.txt` comments |
| Server-side filesystem access is abused | Arbitrary read/write on the user's machine | Three-layer defense in §4.5 — token, Origin check, path sandbox. Non-negotiable, tested in `test_security.py`. |
| Snapshot undo grows memory on large trees | Slowdown on huge analyses | 50-entry cap; measured against a 500-node tree in P5 |
| The vendored core is patched without documentation | The fork becomes unauditable — nobody can say how it differs from baseline | Hash pins in both directions (§4.6); an undocumented patch fails CI. Note the risk is *undocumented* change, not divergence itself — divergence is intended (§1.2). |
| The freeze is broken mid-project by an edit to `src/` | Vendored copies no longer trace to a known baseline | The upstream pin fails on the first change. Applies only through v1.6; after deprecation `src/` is inert by definition. |
| Users lose data moving between the two tools | Migration breaks trust in the new app | JSON round-trip is a hard compatibility requirement (§9) and stays tested for as long as both tools ship. Export-format parity is explicitly not a goal. |

## 15. After v1.6

### 15.1 Deprecating the desktop app

Deprecation happens **once v1.6 ships**, not before — the freeze must hold while the
vendored copies are still being traced to baseline. The desktop app is retired from
maintenance but stays in the repository and stays runnable.

| Step | Action |
|------|--------|
| 1 | `README.md` — mark the desktop app deprecated, point new users to `fta_web/`, keep its run instructions |
| 2 | `CHANGELOG.md` — record the deprecation and the date, name v1.6 as the successor |
| 3 | `docs/` — add a short migration note: JSON files carry over unchanged; Excel output differs for deep-sibling trees (§12, defect 3) |
| 4 | `src/` and `tests/` — retained, untouched, unmaintained. No new features, no fixes. |
| 5 | `BASELINE.json` — the upstream pin stays as a historical record of what was vendored |

**One interaction to be aware of.** The natural way to deprecate a tool is a notice
inside the tool itself — but adding a banner to `FTA_Editor_UI.py` would edit a frozen
file and break the upstream pin. Two options:

- **Documentation-only deprecation** (recommended). `src/` is never touched, the pin
  stays valid forever, and the notice lives in the README and CHANGELOG.
- **A one-time exception**: add the banner, re-pin, and record it in `DIVERGENCE.md` as
  the final upstream change.

Recommended is documentation-only. The pin's value is that it never legitimately
changes; spending that for a startup banner is a poor trade, and users who run the
desktop app directly are the ones least likely to be surprised by its status.

### 15.2 Candidate work for v1.7

All of the following land in `fta_web/` only:

- Implement `NOT` as a real complement gate with defined multi-child semantics, if §12.3 resolved as "reject" in v1.6
- Streaming AI responses and a visual diff preview before applying an AI update
- Per-node "suggest causes here" action
- Minimal cut-set analysis and importance measures
- Optional hosted multi-user mode
